## タスク: ワイルドカード固定行指定構文 `__name#N__` の追加

- **完了日**: 2026-07-06
- **動作確認**: ✅済み（numpy/torch等をモック化したスタンドアロンスクリプトで、フルキャッシュ/no-cache両モード・正常系/各エラー系を確認。一時ファイルは削除済み）
- **新規ファイル**: なし
- **修正ファイル**:
  - `modules/impact/wildcards.py` : `replace_wildcard` 関数に `__name#N__` 固定行選択ロジックを追加
- **変更内容**:
  - `__umamusume_casual__` のようなランダム選択ワイルドカードに対し、`__umamusume_casual#1__` のように末尾に `#N` を付けると、実効行リスト（コメント行・空行を除外後）のN番目（1始まり）を固定選択できるようにした
  - トークン正規表現を `r"__([\w.\-+/*\\]+?)__"` から `r"__([\w.\-+/*\\]+?)(?:#(\d+))?__"` に変更し、`#N` を任意グループとして捕捉
  - `#N` はグロブ（`*`）との併用不可、複数ファイル結合（部分一致・ディレクトリマージ）不可、`.txt` ファイル限定とし、`find_wildcard_file()` で単一ファイルの厳密一致・拡張子を検証
  - 対象ファイルが見つからない/YAML由来/範囲外インデックス（0や行数超過）の場合はいずれも `ValueError` を送出し、ワークフロー実行を停止するハードエラーとした
  - 先頭ゼロは `int()` パースで自然に無視（`#001` = `#1`）
  - 選択した行に既存の重み付き構文（`N::text`）が付いていた場合も、通常のランダム選択と同じ正規表現でプレフィックスを除去
  - ネストしたワイルドカードの再帰展開は `process()` の既存ループでそのまま機能するため追加実装なし
- **備考**:
  - スコープ外（今回未対応）: `count$$__name__` のような動的プロンプト（`{}`）内での `#N` 使用、および外側の繰り返し指定 `N#__name__` との組み合わせ（例: `3#__pose#5__`）
  - 検証時、標準のPython環境に `numpy`/`torch`/`pyyaml` 等が入っていなかったため、`numpy` の最小スタブと `folder_paths`/`nodes`/`impact.utils` のダミーモジュールを用意して `modules/impact/wildcards.py` を単体importし、`process()` の入出力を直接確認する形でテストした
